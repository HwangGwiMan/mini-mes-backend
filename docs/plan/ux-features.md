# 사용자 편의 기능 로드맵

> 작성일: 2026-03-17

## 인증 / 세션

### 1. Refresh Token

현재 Access Token만 발급되어 만료 시 사용자가 작업 중 강제 로그아웃된다.

- Access Token 단기(15분~1시간) + Refresh Token 장기(7~30일) 이중 구조
- Refresh Token은 DB 또는 Redis에 저장하여 무효화 가능하게 관리
- Silent refresh: 클라이언트가 만료 전 자동으로 Access Token 재발급

### 2. 내 계정 관리

- 비밀번호 변경
- 프로필 정보(이름, 연락처 등) 수정
- `employee` 도메인과 연동하여 담당자 정보와 일관성 유지

## 사용성

### 3. 즐겨찾기 / 최근 메뉴

- 자주 쓰는 화면 고정 (즐겨찾기)
- 최근 방문한 메뉴 N건 기록
- 사용자별 서버 저장 → 기기 변경 시에도 유지

### 4. 사용자 설정 (Preference)

사용자마다 선호하는 UI 설정을 서버에 저장하여 어느 기기에서든 동일한 환경 제공.

| 설정 항목 | 예시 |
|---|---|
| 목록 페이지당 건수 | 10 / 20 / 50 |
| 날짜 표시 형식 | YYYY-MM-DD / MM/DD/YYYY |
| 테마 | 라이트 / 다크 |

### 5. 공지사항 / 시스템 메시지

- 점검 예고, 업데이트 안내 등 운영 메시지
- `notification`(개인 알림)과 별개로 전체 사용자 대상 브로드캐스트
- 관리자가 등록, 유효 기간 설정 가능

---

## 검색 / 탐색

### 6. 글로벌 검색

- 수주번호, 품목명, 거래처명 등 주요 엔티티를 한 곳에서 검색
- 결과 클릭 시 해당 화면으로 바로 이동
- 도메인이 충분히 쌓인 후 구현 효과 극대화

### 7. 필터 저장 (Saved Filter)

- 자주 사용하는 조회 조건을 이름 붙여 저장 및 재사용
- 예: "이번 달 미완료 수주", "거래처 A 출하 목록"
- 사용자별 저장, 공유 필터는 추후 확장

---

## 감사 / 추적

### 8. 활동 로그 (Audit Log)

현재 `BaseEntity`의 `createdBy` / `updatedBy`는 최신 상태만 보존하므로 변경 이력이 남지 않는다.
제조업 특성상 누가 언제 어떤 데이터를 변경했는지 추적 요구가 강하다.

- 중요 액션(수주 상태 변경, 출하 처리, 작업지시 완료 등) 별도 이력 테이블 저장
- 조회: 특정 엔티티의 변경 이력 타임라인
- Spring AOP 또는 JPA `@EntityListeners` 활용 구현 고려

## 구현 우선순위

| 우선순위 | 기능 | 이유 |
|---|---|---|
| 높음 | Refresh Token | 실사용 시 가장 먼저 불편함을 느끼는 부분 |
| 높음 | 활동 로그 | 제조업 특성상 변경 이력 추적 요구가 강함 |
| 중간 | 공지사항 | 운영 시 점검 안내 등 실무 필수 |
| 중간 | 사용자 설정 | 목록 건수 등 사용자마다 선호가 달라 민원 발생 소지 |
| 낮음 | 글로벌 검색 | 도메인이 충분히 쌓인 후 효과 극대화 |
| 낮음 | 즐겨찾기 / 필터 저장 | 메뉴 구조와 UI 완성도가 높아진 후 의미 있음 |
